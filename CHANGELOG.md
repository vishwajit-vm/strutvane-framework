# @strutvane/framework

## 0.2.0-next.1

### Patch Changes

- 2cd9d0b: Models now work inside an `Application`'s requests and commands. In 0.2.0-next.0 the v2 `Application` opened no database connection, so ORM models could query from `node strut` commands (seeders) but not from a controller or route. Booting the app now hands the ORM `.strutvane/schema.json` and the tenancy switch (`config/tenancy.ts`) and binds `DatabaseConnectionToken` (exported from `@strutvane/framework`): the default connection from `config/database.ts` over `DB_*`, opened lazily by the first query (requests that never query, such as `/up`, never need the database) and closed on `app.shutdown()`. Each app's requests and commands use that app's own connection; with tenancy on, the request's tenant (from an `http.onRequest` hook) scopes every model query. `APP_ENV=testing` uses `database.test_database` when set. Bind `DatabaseConnectionToken` before boot to use another connection. New in `@strutvane/framework/database`: `openDatabaseLazily(settings)` and `runWithConnection(resolve, work)`.
- 8e88e94: The framework's `strutvane.compat` now accepts its own 0.2 release train (`^0.2.0-next.0`). In 0.2.0-next.0 it still said `^0.1.0-next.0`, so the 0.2 CLI refused the framework's own `migrate`, `db:seed`, `sync`, `start` and `dev` commands in a 0.2 app. The CLI also never refuses the package it ships in at its own version, and the advice it gives plugin authors without a range (`node strut doctor`, the `missing_compat` hint) now names the running CLI's train instead of a fixed `^0.1.0`. A test fails whenever the range stops accepting the package's version, so the next version bump can't repeat this.
- e937372: `ConfigOf` and `RoutesOf` are now exported from `@strutvane/framework`, so an app can write the typed-registry block the docs describe (`interface RouteRegistry extends RoutesOf<[typeof web, typeof api]> {}`, `interface ConfigRegistry extends ConfigOf<typeof config> {}`) importing only from the package. In 0.2.0-next.0 they existed but were not exported.
- 9f4c0aa: Projects reached through a symlink or junction (for example any temp folder on macOS, where `/var` links to `/private/var`) now work like projects reached by their real path. `node strut migrate --seed` and `db:seed` find and name every seeder, and policy boot errors name the file inside the app. The project root is now resolved to its real path once, before anything else runs. Symlink protections are unchanged: a link inside the project that points outside it is still refused.
- 2ec0b7a: The migration replay sandbox's timeout can now be raised: `--replay-timeout=30s` on `migrate`, `migrate:status`, `migrate:rollback`/`reset`/`refresh`/`fresh`, `db:seed` and `sync`, or `DB_MIGRATION_REPLAY_TIMEOUT=30s` in `.env` (the flag wins). The default stays 10 s; values must be from 1 s to 10 min (`30000`, `30s`, `2min`) and anything else is refused naming the flag or key. `replayInSandbox(dir, { timeoutMs })` checks the same bounds, and the timeout error now says how to allow more time.
- 5bbd00a: `.strutvane/resources.json` no longer exposes framework or identity tables and takes mass assignment from the models. In 0.2.0-next.0 tables such as `sessions`, `cache`, `cache_locks` and `password_reset_tokens` became sidebar resources unless their migration said `{ internal: true }`, and `fillable` came from the migration, so `users.email_verified_at` was fillable although `User` allows only `name` and `email`.
  
  - Every table on `INTERNAL_TABLES` (the list the resource controller already refuses, security review F-01) is now listed under `internal` instead of `resources`, together with `{ internal: true }` tables, and relations to them are left out. This includes `users` and `teams`: they get no auto CRUD or sidebar entry (`@strutvane/auth` provides the users screen).
  - `sync` and `migrate` read `fillable`, `hidden` and `allowSensitive` from `app/models` without running them. A field is fillable only when the table's model lists it, and a model with no `fillable` makes nothing fillable. Secrets, hidden columns and privilege-like names (`is_*`, `*_at`, `role`…) need `allowSensitive` too. Without a model, only plain columns are fillable. Model options that aren't literal string arrays produce a warning and nothing fillable (fail closed).
  - `primaryKey` is the table's real primary key (`t.uuid('code').primary()` gives `code`), not always `id`.
- bcd30a5: `createTestApp()` from `@strutvane/framework/testing` accepts a `clock` option. Pass a `createTestClock()` to test anything time-based, such as idempotency TTLs or expiry, by moving time yourself. Tests then neither wait nor fail on a slow machine.

## 0.2.0-next.0

### Minor Changes

- 9fbd206: The v2 application core (Laravel's flow): `Application.configure({ basePath }).withRouting().withMiddleware().withExceptions().withCommands().create()` in `bootstrap/app.ts`, routing (`Route`, `defineRoutes`, resources, signed URLs, a typed callable `route()`), the HTTP kernel with middleware and protections, form requests, the exception handler and dev error page, the security kit (keyring with `APP_PREVIOUS_KEYS`, one URL signer, AES-GCM, SSRF-safe `HttpClient`, CORS, CSP nonces), maintenance mode, the cache (`memory`, `file`) and session stores, facades on the new `@strutvane/framework/facades` subpath, and the app commands (`optimize`, `config:cache`, `route:cache`, `event:cache`, `route:list --security`, `key:rotate`, `env:encrypt`/`env:decrypt`, `down`/`up`, `cache:clear`, `session:flush`, `security:check`, `make:command`/`make:rule`/`make:observer`).
  
  `node strut start`/`dev` serve `bootstrap/app.ts` (booted before the port opens); the Node adapter passes the socket peer and `waitUntil`; `trustProxy` accepts a list of proxy addresses or CIDR ranges; HSTS is sent in production only; `node strut list` is the listing command (`help` is an alias); every message says `node strut`.
  
  **Breaking (pre-1.0, CONSISTENCY #123):** every error code is now lowercase `snake_case` (`NOT_FOUND` → `not_found`, `VALIDATION_FAILED` → `validation_failed`, CLI and devkit codes alike). The old names keep working through 0.2 with a `DeprecationWarning`; `LEGACY_ERROR_CODES` lists every rename. Validation issues gain a `field` member with the dotted path (CONSISTENCY #69).
- 2943aaa: The v2 data layer: migration-first schema and Strutvane's own ORM (blueprint §2.3, §2.4, §4).
  
  **Migrations are the source of truth.** `database/migrations/*.ts` use Laravel's Schema builder
  from the new `@strutvane/framework/schema` entry (`schema.create('posts', (t) => { … })`, with
  `.secret()`, `.hidden()`, `t.tenant()`, `{ global: true }`, `{ internal: true }`, UUIDv7 keys and
  tenant-safe composite keys). They are replayed offline, in a sandboxed child process (no secrets,
  no network, a timeout, symlinks refused), into `.strutvane/types/models.d.ts`,
  `.strutvane/resources.json`, `.strutvane/schema.json` and per-engine SQL.
  
  **The ORM** (`@strutvane/framework/database`): `class Post extends Model('posts', { fillable })`,
  a typed query builder, relations, casts, scopes, soft deletes, slugs, pagination, transactions
  with savepoints, the tenant scope, and `wherePolicy()` for ADR-0008 policy filters. It runs on
  MySQL 8.4+ (the default), MariaDB, PostgreSQL (node-postgres or PGlite) and SQLite (`node:sqlite`).
  PostgreSQL tables with `t.tenant()` get ADR-0007 row-level security from their migration.
  
  **Commands** for migration-first projects: `migrate` (`--pretend`, `--step`, `--seed`, `--force`,
  `--isolated`), `migrate:status`, `migrate:rollback`, `migrate:reset`, `migrate:refresh`,
  `migrate:fresh`, `db:seed` (`--class`, `--tenant`, `--force`), `sync`, and `make:migration`
  (writes the model; `--seeder` adds the seeder and factory). Production needs `--force`.
  `defineSeeder({ after, run })` and `defineFactory(Model, ({ faker, sequence }) => …)` are new.
  
  **Configuration:** `DB_CONNECTION` = `mysql` | `mariadb` | `pgsql` (`postgres` accepted) |
  `sqlite`, plus `DB_URL`, `DB_SOCKET`, `DB_SSLMODE` and `DB_SSL_CA`. `mysql2` is a new optional
  peer dependency.
  
  **Upgrading from 0.1 (breaking, pre-1.0):**
  - v1 (`defineModel`) projects keep working: the commands detect them and run the v1 path.
  - Drizzle-based planning (`planMigration`, `compilePg`, `compileSqlite`, `writeMigration`,
    `migrateProject`, …) is deprecated and will be removed in 0.3. Move models' columns into
    migrations, then use `node strut migrate`.
  - `defineSeeder({ run })` (object form) now receives the migration-first context
    (`{ db, env, tenantId, faker, call }`); the string form keeps the v1 context.
  - Tenancy in the ORM is off unless enabled (`config/tenancy.ts`), and a `t.tenant()` table is
    refused while it is off.
  - New error codes are lowercase `snake_case`; existing v1 codes are unchanged in this release.

### Patch Changes

- c762578: Security hardening of the v2 data layer (migration replay sandbox and ORM).
  
  **Replay sandbox.** The static gate and the child process now resolve relative imports with one
  shared function that accepts only plain `./`/`../` paths ending in `.ts`. The child loads only
  the files the gate approved, pinned by SHA-256 and always as ES modules. It checks its own
  confinement before running anything, empties its global scope to an allowlist, freezes what is
  left, and runs with frozen intrinsics, a heap cap and no addons. Text from a failing migration is
  stripped of control characters before it is shown.
  
  What may break a migrations folder:
  - A `package.json` or `node_modules` inside `database/migrations` is refused.
  - `module`, `exports`, `__dirname`, `__filename`, `import x = require()` and `export =` are refused.
  - Column sizes are bounded: length 1–65,535, precision 1–65, scale up to the precision.
  - One migration may record at most 1,000 operations.
  
  **ORM.** Columns that the migration marks `.hidden()` or `.secret()`, and columns named like secrets,
  are hidden from every model without listing them in `hidden`. The secret names are `password`,
  `*_token`, `*_secret`, `api_key`, `private_key`, `*_access_key`, `recovery_codes` and the like, and
  they are now shared with the type and metadata generators. A hidden column is never included in:
  - `toJSON()`
  - `util.inspect`
  - request filters, sorts and searches
  - `cursorPaginate()` sort keys (refused with `cursor_hidden_column`)
  - "did you mean" hints
  
  A secret column in `fillable` must also be listed in `allowSensitive`, otherwise it is refused with
  `secret_fillable`. The conditions a relation, `whereHas`, an eager load or a cursor adds can no
  longer be OR-ed away by `orWhere`. Request text for contains/startsWith is capped at 200
  characters, and `sort()` takes at most 8 columns. `SqlFragment.trusted` is gone: fragments come
  only from the `sql` tag, and every identifier is checked again when the SQL is rendered.

## 0.1.0-next.1

### Minor Changes

- 67346c9: Custom route handlers get the app's services: `repository(model)`, `scope`, `scopeFor(model, action)` (tenant plus policy filter), `authorize(permission, record?)`, `storage`, `app` and `multipart(limits)` (temp files always cleaned up), plus a per-route `bodyLimit`. The project runtime reads `config/filesystems.ts`, signs temporary links with `APP_KEY` and serves them at `/storage/<disk>`, and `sv start` serves the built UI from `dist/web` (`createHttpApp({ staticFiles })`).
- b82c67b: The CLI now identifies as `@strutvane/framework` (B6): `sv about`, `sv help` sources, generated headers and project detection (a package.json that lists `@strutvane/framework` is a project; `@strutvane/cli` still counts for older apps). `sv doctor` checks that the framework is a dependency, gives the install command for the project's own package manager, and fails when `@strutvane/core`, `contracts`, `devkit`, `cli` or the `strutvane` launcher is declared or installed next to it (two kernels, duplicate bins), with the command that removes them. Node.js 24.3 or newer is required (`engines` and `sv doctor`).
- 1e34ef1: Gate package migrations (they run as the database owner): `ctx.packageMigrations()` returns the migration folders of packages that are direct dependencies with a contributor name, enabled by a value import in `strutvane.config.ts`, compatible (`strutvane.compat` required for third-party packages, exit 7), and whose folder resolves inside the package in `node_modules` (`UNSAFE_CONTRIBUTION`). `sv migrate` (from `@strutvane/framework`) applies only those. `sv doctor` warns about dependencies whose migrations are ignored and fails on an enabled package that fails the gate.
- 0d9dbbf: CSRF protection is on by default. Every POST, PUT, PATCH or DELETE that carries the session cookie must come from the app's own pages (`Sec-Fetch-Site: same-origin`, an exact `Origin`, or a token in `X-XSRF-TOKEN`, `X-CSRF-TOKEN` or a form's `_token`), otherwise it gets a 419 problem with code `csrf_token_mismatch`. This covers the CRUD routes (restore included), custom routes with or without a body, and routes a request hook answers. The framework sets an `XSRF-TOKEN` cookie for front-end code, kept in step with the session. Bearer-token requests without the session cookie are not checked. The session cookie's name has one source, `config/session.ts` `cookie` (default `strutvane_session`, `__Host-` added on https), published as `SessionCookieToken`; callback paths a third party posts to go in `config/session.ts` `csrf.except`. Error codes may now be `snake_case`.
- fa7cfed: `sv db:seed --tenant <id>` seeds a tenancy app: seeders get `scope` (`{ tenantId }`) and `tenantId`, and `create(factory, count)` uses the run's scope by default. Without the flag, a tenant-scoped model now fails with a validation error that names `--tenant` instead of `TENANT_REQUIRED`; a malformed id is refused before anything runs. `sv make:seeder` generates `async ({ create, scope }) => { await create(Factory, n, scope) }`.
- bfefa42: `sv dev` serves the API and the web UI on one port: it mounts the project's own Vite (resolved from the project's `node_modules`, so the framework has no Vite dependency) in middleware mode, with HMR over the same server, for `GET`/`HEAD` requests the API did not answer outside the API base path and framework paths. Without a `vite.config.*` or an installed `vite`, it serves the API only and says so. New building blocks: `createHttpApp({ uiFallthrough })`, `serve({ prepare, fallback })`, `startServer({ vite })`, and one shared rule for the paths the UI may answer (also used for `dist/web` in `sv start`). `sv build` finds any `vite.config.*` and the project's Vite the same way.
- e2e8f26: `GET /docs` serves a readable page for the OpenAPI document, next to `/openapi.json` and under the same visibility rule (public in `APP_ENV=local` or when `openapi: 'public'`, identified callers elsewhere, absent with `openapi: false` / `API_DOCS=false`). It is server-rendered with no scripts, a CSP that allows only inline styles, and every document value escaped.
- 151fd11: Safer defaults across the API, runtime and storage:
  
  - Hidden fields are never writable and cannot be filterable, sortable or searchable; hidden and sensitive field keys are registered for log redaction at boot (core `registerSensitiveKeys`).
  - Creates and updates are checked against the actor's policy filter after the write, in the same transaction (`Scope.check`); record-level `can()` for updates sees the resulting row; `resource.beforeQuery` results are combined with the policy filter; `belongsTo` references must be visible to the actor (`Scope.references`).
  - List cost limits: offset pages up to `MAX_OFFSET` rows deep, totals only with `allowTotal: true`, `pageSize.max` applied to `POST /query`, deduplicated and capped includes, and a default 5 s Postgres `statement_timeout`.
  - Client filters reject `$actor` references and malformed nodes (422 `invalid_filter`); custom route `json()` requires a JSON content type.
  - The manifest lists only resources the caller can use; `/openapi.json` is for identified callers outside local development (`openapi` option).
  - HTTP hook payload types and names now come from `@strutvane/contracts` (re-exported); `http.onRequest` receives `clientAddress`. New `trustProxy` and `publicUrl` options (HSTS behind a TLS-terminating proxy; forwarded headers and `X-Request-Id` only from trusted proxies) and a `Permissions-Policy` header.
  - `serve` aborts `request.signal` on disconnect, cancels response bodies, honours backpressure and does not stream `HEAD` bodies; handlers receive `{ incoming, clientAddress }` as a second argument.
  - Uploads: a total deadline (`totalTimeoutMs`), the idle timer reset by every byte, prototype-free field maps, stricter active-content detection, and wildcards that never match active content. Storage keys are lowercase without trailing dots or device names; `storage.forTenant()` and `store(…, { tenantId })` scope keys per tenant. Signed URLs use an HKDF subkey; `serveSignedFile` and `createHttpApp({ signedFiles })` serve them.
  - `tenancyAudit()` also checks table ownership, view `security_invoker`, `SECURITY DEFINER` functions and the tenant expression of restrictive policies.
- 3be28e6: Resource hook contexts gain `repositoryFor(model)`, `scope` (the request tenant) and `app`, so a hook can update another model (invoice totals from its lines) or clean up stored files.
- 9516e2a: `Idempotency-Key` is honoured on POST and DELETE: CRUD create, delete and restore, and custom routes. A retry with the same key and body gets the first response replayed (`Idempotent-Replayed: true`, with only `content-type` and `location` restored) instead of running the action twice; the same key with a different body, method or path is a 422 `idempotency_key_reused`; a duplicate while the first is still running is a 409 `idempotency_in_progress`; a malformed key is a 400 `idempotency_key_invalid`. Keys are scoped to the caller and tenant. 5xx answers are not stored, so the retry runs for real. The in-memory store keeps at most 10,000 keys for 24 h (`createHttpApp({ idempotency: { ttlMs, maxEntries } })`); bind `IdempotencyStoreToken` for a shared store in a cluster.
- c40be97: `sv migrate` (and `migrate:status`) also apply migrations shipped by packages: a package declares `"strutvane": { "migrations": "./migrations" }` and ships `<folder>/<dialect>/*.sql`, applied and drift-checked like the app's own files (`readPackageMigrations`, `MigrateProjectOptions.packageMigrations`).
  
  Security: these run as the database owner, so the framework never scans `node_modules`. It reads only the folders the CLI vetted (`ctx.packageMigrations()`: enabled in `strutvane.config.ts`, direct dependency, contributor name, compat, real path inside the package), and each dialect folder and file must resolve inside its package. Without that list nothing runs (fail closed). `migrate --pretend` lists package migrations with their package, `migrate:status` has a Source column, and `Applied …` lines name the package.
  
  Pre-release caveat: an app created before this release may have committed `database/migrations/*_auth_identity.sql` (written by the old `sv auth:migration`). On a fresh database, delete that file: `@strutvane/auth` now ships the same tables as a package migration. On a database where it was already applied, keep it (deleting an applied migration is reported as drift); the package migration is idempotent (`CREATE TABLE IF NOT EXISTS`) and records itself under its own name.
- cdbfc5a: Add the `resource.beforeWrite` hook (create and update, before the database) and a `type` (permission prefix) on `resource.serialize` payloads, so a permission package can enforce field-level read and write rules. A Strutvane error thrown by a hook handler now keeps its status instead of becoming a 500.
- 2451dda: Seeding: `related('Model')` in a factory now reuses an existing parent in the same tenant (spreading children over the first 100 in turn) and creates one only when none exists; `related('Model', { create: true })` keeps the old always-create behaviour. `sv db:seed` warns, naming the files and the fix, when `DatabaseSeeder` ran no other seeder while other seeder files exist. The documented seeder shape is `defineSeeder('Name', async ({ call, create }) => …)`.
- 1391b8b: A Host allowlist now guards every request in every environment, local development included. `localhost`, `127.0.0.1`, `[::1]` and the `APP_URL` host are always allowed, plus `config/app.ts` `trustedHosts` (exact names or `*.example.com`); any other `Host` (or, behind a trusted proxy, `X-Forwarded-Host`) gets a 400 problem with code `untrusted_host` before any hook or route runs. This stops DNS rebinding of the dev API and dev UI and host-header poisoning in production. If you reach a dev server by a LAN address or another name, add it to `trustedHosts`.
- faa08a8: `policySchema(Model)` is typed per field (`PolicySchemaOf<M>`), so policy rules over framework models type-check instead of failing with "possibly undefined" columns; field builders carry their kind as a phantom type. Custom route `params` are typed from the path (`RouteParams<P>`), and route handlers get `where(model, filter)` to bind server-written filters for repository calls.
- 6b9bf82: Write hooks run in two stages. The new `onWrite(change, ctx)` resource hook and the `resource.onWrite` hook run inside the write's transaction (with `ctx.db`, and repositories bound to it): a failure rolls the write back and answers with that error, which is where audit records belong. After the commit, `after*` hooks, the new `afterCommit(change, ctx)` hook, `resource.afterCommit` handlers and the domain event run; a failure there is logged and no longer turns the response into a 500 for a write that succeeded. Repository writes accept `{ onWrite(record, tx) }` for the same guarantee in custom code.

### Patch Changes

- 67346c9: `serve` no longer adapts request bodies with `Readable.toWeb`: a body the app stops reading (a body limit, an upload aborted by the multipart parser) is drained up to 1 MiB so the client receives the 413/422 problem instead of a connection reset, and it can no longer raise an uncaught "Controller is already closed" error.
- 725f202: `APP_ENV` is trimmed and lowercased everywhere (an empty value counts as unset), matching the CLI. Contributed commands use the value the CLI resolved (`ctx.appEnv`, else `ctx.services.env.APP_ENV`) instead of re-reading `.env`; `loadProject(root, { appEnv })` applies it before config loads.
- 7145484: Custom routes' `scopeFor` now builds the row filter exactly as the CRUD routes do: `resource.beforeQuery` hooks narrow it, and a policy that cannot be bound (an unknown field, a missing actor attribute) is a 500 instead of a 422 that named the policy's fields.
- 0fcce96: Includes follow field-level read rules: when the PermissionProvider implements `filterableFields`, an include is refused (`include_not_allowed`) unless the actor may read its link field (the `belongsTo` field, or the target's foreign key for a `hasMany` relation), on list, show and `POST /query`.
- 1d55a1a: `serve` appends the request path to the bind or public origin instead of resolving it as a relative URL, so no request target can change the origin the app sees in `request.url`.
- f1322fc: Create and update validation now accepts only values every engine can store: 64-bit range for `bigInteger`, years 0001-9999 (after converting to UTC) for `date` and `datetime`, and no U+0000 inside `json` values. Such values used to pass validation and fail on write as a 500; they are now a 422 on the field, and the same dates as filter operands are a 422 too.
- 09dae50: `tenancyAudit` now requires a tenant table's restrictive policy to be exactly the tenant comparison in both `USING` and `WITH CHECK`; a policy that mentions the tenant setting but ORs anything else in is reported as `tenant-policy-mismatch`.
- 2c33066: `PATCH /<resource>/:id` checks that the caller may update some rows before it reads and validates the body, so an anonymous or unauthorized caller gets 401/403 instead of field-level validation issues describing the schema.
- 671eb76: `bootProject()` (used by `sv start`, `sv dev` and `startServer()`) shuts the app down again when a provider fails to boot, so the providers that had already booted release their connections, pools and timers instead of keeping the process alive after the error. Booting is also bounded: a provider whose `boot()` never settles fails with `BootTimeoutError` after `bootTimeoutMs` (default `DEFAULT_BOOT_TIMEOUT_MS`, 30 s) instead of hanging `sv start` forever.
- c17dee8: `sv start` and `sv dev` now check the settings the framework reads before booting, and a malformed one stops the boot with exit 3 and an "Invalid environment" message naming the key, instead of booting with a broken value or exiting 1 with a driver error: `APP_TIMEZONE` (an IANA zone), `APP_LOCALE` (a language tag), `API_PREFIX` (a path starting with `/`), `CORS_ORIGINS` (exact origins, no `*` or paths), `TRUST_PROXY` (0–32; empty is refused), `APP_URL` (an http(s) URL) and `DB_DATABASE` (a SQLite file whose folder exists, not a folder). Every problem is listed at once and values are never printed.
- 4dd004d: The `bin` entries in package.json no longer start with `./`, so npm publishes them as written instead of reporting them as auto-corrected.
- a33bdac: `sv dev` and `sv build` handle a child process that cannot start (a missing working directory, descriptor or process exhaustion): it counts as exit code 1 instead of crashing the CLI with an uncaught `error` event or waiting forever for an `exit` that never comes. `sv dev` also removes its Ctrl+C/SIGTERM forwarding listeners once the child is gone. Both use the new `runChild()` helper.
- c627885: Safer defaults across the CLI:
  
  - Project detection matches the launcher: a project is a folder whose package.json lists `@strutvane/cli` or that contains `strutvane.config.ts`, never a drive root, the temp folder or a folder above home, and on POSIX one owned by the current user.
  - `APP_ENV` is resolved as the runtime does (process environment, then `.env.<name>` with `--env`, then `.env`; empty means unset; trimmed and case-insensitive). Destructive commands run without confirmation only in `local`, `test`, `testing` or `development`; otherwise they need `--force --i-understand`. Commands receive the resolved value as `ctx.appEnv` and can call `ctx.guardDestructive()`; `--env <name>` now loads `.env.<name>` for the command.
  - Destructive commands must be typed in full (no prefix matching).
  - `key:generate --force` is guarded the same way when it replaces a key, and replaces every `APP_KEY` line.
  - `env:check` and `doctor` report malformed env lines and invalid keys by file and line number only.
  - On Windows, programs are resolved from PATH (never the working directory) and child processes get `NoDefaultCurrentDirectoryInExePath=1`.
  - Generator inputs are validated against the field catalogue (types, modifiers and argument formats), and numbers are re-checked when templates render.
  - The field parser only accepts the catalogue's own entries, and `make:*` refuses names that would create Windows device file names.
  - Plugins outside `@strutvane/` must declare `strutvane.compat`; manifest text is printed without control characters.
  - `registry:build` refuses to write through a symbolic link or junction at `.strutvane`.
- a636a6e: `sv add <package>` installs Strutvane packages from the CLI's own release channel (`@strutvane/auth@next` while the CLI is a `next` prerelease; the bare name for a stable CLI), because before 1.0 a bare name resolves the npm name placeholder. Third-party plugins are still installed by their bare name. The `doctor` hint for a missing `@strutvane/cli` names the same channel.
- e556278: The package-migration gate now reads which packages `strutvane.config.ts` enables by parsing its imports. An import inside a block comment or a string, or one that imports only types, no longer enables a package's migrations, and a config file that does not parse enables none.
- dacb840: An invalid app environment is reported as a configuration error instead of an unexpected one. When a command (built-in or contributed) fails with core's `EnvValidationError`, also when it arrives as the `cause` of another error, the CLI lists each problem by variable name, prints how to fix the `.env` file, and exits with code 3 (validation). The error code in the `--json` envelope is `ENV_INVALID`. The error is matched by its `name` and `problems` list, so a contributed command that bundles its own copy of core is classified the same way.
- 1293d04: A contributed command whose exact name is also an abbreviation of a built-in (for example a plugin's `make:mod` next to the built-in `make:model`) now runs, instead of the built-in. An abbreviation that fits both is reported as ambiguous.
- 2e957fe: Field specs accept square brackets wherever they accept parentheses: `name:string[120]:required`, `amount:decimal[12,2]:min[0]`, `status:enum[draft,paid]:default[draft]`, `customer:belongsTo[Customer]`. Both spellings mean the same. On Windows, PowerShell runs `corepack pnpm sv`, `pnpm sv` and `npx` through `.cmd` shims, where parentheses in an argument fail with "… was unexpected at this time" before the CLI starts; brackets and commas pass through unchanged. Inside brackets, quote text with single quotes (`"due:date:label['Due date']"`), because PowerShell 5.1 drops double quotes inside an argument. `sv help make:model` shows the bracket form first on Windows, and `formatFieldSpec(field, { brackets: true })` prints it.
- dad6777: `sv key:generate --force` now replaces an `APP_KEY` on the first line of a `.env` saved with a byte-order mark. Before, it reported success and left the old key in place.
- c627885: Project detection is stricter: the launcher delegates only to a folder whose package.json lists `@strutvane/cli` or that contains `strutvane.config.ts`, never to a drive or file-system root, the OS temp folder or a folder above the home directory, and (on POSIX) only to folders owned by the current user. `--version`, `help`, `new` and `create` are always answered by the launcher itself. `npx` now runs as `node npx-cli.js` without a shell when available; the Windows fallback resolves `npx.cmd` from PATH only and child processes get `NoDefaultCurrentDirectoryInExePath=1`. Text read from manifests is printed without control characters, and an invalid `STRUTVANE_CREATE_COMMAND` is reported instead of crashing.
- a636a6e: `strutvane new` and `strutvane create` run `create-strutvane` from the launcher's own release channel: a `0.1.0-next.N` launcher runs `create-strutvane@next`, a stable launcher `create-strutvane@latest`. Previously `@latest` was always used, which before 1.0 resolves only the npm name placeholder and fails with "could not determine executable to run". The channel is the prerelease id, derived as the release workflow derives the dist-tag; anything that is not strict semver or not a plain lowercase id falls back to `latest`. `help` and the "needs a Strutvane project" message name the same channel (`pnpm add -D @strutvane/cli@next`), and `doctor --global` never passes a version that is not strict semver to npx.
- f8cc305: When `sv dev` or `sv start` cannot bind its address (the port is taken, a privileged port, an interface the machine does not have), the CLI now reports a configuration error that names the host and port and how to change them (`APP_PORT` in `.env`, or `--port`), with exit code 3, instead of "Unexpected error … report the bug".
- 7840aa2: `make:policy` templates use the role names of `config/auth.ts` (docs/07 §2.7): `admin`, `member`, `viewer`, and `owner` for a tenant's creator. Readers now include `viewer`; the `owner` template limits own-record rules to `member`; the `tenant-admin` template grants writes to `admin` and `owner` with `scope: 'tenant'` instead of a `tenant-admin` role no app defines. Long rules are printed the way Biome formats them.
- 1e34ef1: The "No Strutvane project found" hint also names the ownership rule: on Linux and macOS the project folder must be owned by the user running the command (a root-owned folder in a container used to fail with no clue why).
- 2e957fe: `make:model` (and `make:seeder <Name> --model <Model>`) register the new seeder in `database/seeders/database.seeder.ts`, the only seeder `sv db:seed` runs, so seeded models get rows. The command adds the import (in Biome's import order) and `await call(XSeeder)`, and gives the callback a `({ call })` parameter. Calls are ordered so a model's parents are seeded before it; a parent that has no registered seeder yet is named in a warning. Running it again changes nothing. A missing file is created in the shape `create-strutvane` generates, and the starter's older `defineSeeder({ async run() {…} })` file is updated to that shape. Any other content is left as it is, and the lines to add are printed instead. `--dry-run`/`--diff` include the change, `--no-seeder` skips it, and `--json` reports it as `seederRegistration`.
- 054f0f5: `registry:watch` runs one catch-up rebuild shortly after it starts, so a change made while the native file watchers are still starting (notably on macOS) is no longer missed.
- 102c407: `sv registry:watch` no longer hangs after a failed start. When the first build failed (for example because `.strutvane` is a link), the error was reported but the file watchers it had already opened kept the process alive; they are now closed before the error is thrown.
- cd2ce27: The container no longer creates a singleton (or scoped instance) in a container that was already disposed. A request scope still running during shutdown used to recreate app-wide services such as a database pool whose cleanup never ran, which could keep the process alive; it now gets a `DISPOSED` error.
- a942a61: `defineEnv` errors never show a variable's value, even when the validator quotes the received input in its message (some Standard Schema validators and custom messages do). The value is replaced with `[REDACTED]`; values shorter than four characters are left as they are.
- 5f2be24: The logger keeps fields whose key is `__proto__` (common in parsed JSON) instead of silently dropping them from the log line, and still redacts sensitive keys inside them.
- c5b009b: Message lookups and placeholders only use a catalog's or the caller's own entries. A message key or placeholder named like a built-in object member (`constructor`, `toString`, `__proto__`) is now reported as missing instead of resolving to a JavaScript function and printing its source.
- 4ab32e2: `toProblem` no longer degrades a validation problem to a 500 when an issue path is named after an `Object.prototype` member (`__proto__`, `constructor`, `toString`, a client-sent unknown field): `fieldErrors` is built from own properties only and labels are read with own-key checks.
- f2cf40a: The default logger redacts more sensitive keys (`passphrase`, `salt`, `jwt`, `bearer`, `session`, `accessKey`, `signingKey`, `encryptionKey`, `totp`, `mfa`, `recoveryCode`, `backupCode`, `cardNumber`, `cvv`, `iban` and others), and short words such as `pin`, `ssn` and `otp` now match as whole words only. New exports: `DEFAULT_SENSITIVE_WORDS`, `normalizeSensitiveKey`, `registerSensitiveKeys` (add keys at runtime for every logger in the process) and the `SensitiveKeyMatcherOptions` type for `sensitiveKeyMatcher`.
- 96f78a0: `POST /<resource>` answers an anonymous caller who may not create with a plain 401 before reading or validating the body, so validation issues no longer describe the model's fields to someone who may not use it. Authenticated callers are still validated first and then authorized with the input.
- 493db6e: Generators and installers on Windows ride out files that another process holds open (antivirus scanners, indexers, editors), for up to about 3 s instead of 0.3 s, before a change is rolled back. `make:model --force` over a file that a scanner had just opened used to fail with `TRANSACTION_ABORTED` (EPERM on rename). Each wait is capped at 500 ms, so a file that stays locked still fails the change instead of hanging the command.
- 65a3ced: Values written to `.env` files now read back unchanged with the runtime loader. A value containing `"` or `\` is single-quoted (taken literally) instead of escaped, because Node's `.env` parser does not understand those escapes. A value that no quoting style can carry unchanged (one with both `'` and `"`, or a control character) is refused with `INVALID_ENV_VALUE` instead of being written in a form the app would read differently. The CLI's `.env` checks also read values containing U+2028 or U+2029.
- 53a050f: Path checks now follow dangling symbolic links to their target, so a link that points at a protected location (such as a file under `.git/` that doesn't exist yet) is refused like any other protected path. Link loops are refused instead of hanging.
- 147bcf9: Harden file safety in transactions, recovery, previews and env handling.
  
  - Paths under `.git/`, `node_modules/` and `.strutvane/staging/` (at any depth) are refused with `INVALID_PATH`, including through letter case, Windows aliases and links. The rest of `.strutvane/` stays writable.
  - Transaction recovery validates every journal before changing anything, only restores project files plus `.strutvane/lock.json` and `.strutvane/base/**`, only replaces or unlinks single regular files, and refuses journals owned by another user. New `planRecovery()` lists the affected paths; `recoverTransactions({ confirmed })` recovers exactly that plan.
  - File permissions are preserved when a file is replaced. New `.env`/`.env.*` files, backups and journals are created owner-only, staging folders are owner-only, and a linked `.strutvane` or `.strutvane/staging` folder is refused.
  - Diffs redact the values of `.env`/`.env.*` files (except `.env.example`) by default; `StagedFs.diff({ revealSecrets: true })` opts out.
  - `looksSecret(key, value?)` recognises more secret-looking names (`*_PASS`, `*_PWD`, `*_DSN`, `SALT`, `SIGNING`, `ACCESS_KEY`, …) and URLs with embedded credentials, which therefore never reach `.env.example`.
  - `DevkitIo` gains two required methods, `removeFile` and `inspect`, and `writeText` accepts an optional `{ mode, dirMode }`. Custom implementations that spread `nodeIo` keep working; others must add the two methods.
- 2621960: Devkit creates folders (`mkdir -p` before writing or renaming a file) with the same bounded Windows retry as renames. A filter driver briefly refusing to create a parent folder made Node report ENOENT for the new folder and rolled the whole change back.
- e2cab6c: File transactions are sturdier on Windows. Renames and deletes retry briefly while another program (an antivirus scanner, an indexer, an editor) holds the file, instead of rolling the whole change back. The transaction journal is now deleted before the rest of the staging folder, so a failure to clean up after a successful change can no longer leave a journal that would make `sv recover` undo it.
- bb77acb: Factory definitions and overrides (`defineFactory`, `create`, `createMany`, `attributes`) accept every column of the model, `readOnly` and `hidden` ones included, typed per field (`FactoryAttributes<M>`), so tests and seeders no longer need casts. `readOnly` is an API rule for clients; system columns (`id`, timestamps, `deletedAt`) stay out.
- 11ebc11: List queries honour `PermissionProvider.filterableFields` when the provider implements it: filters, sorts and `POST /query` accept only the returned fields (422 otherwise), and search skips searchable fields outside the set. Providers without the method behave as before. New helper: `narrowQueryFields`, plus `ListOptions.allowedFields` on the repository.
- 8dcf1b4: Graceful shutdown for `sv start` and `startServer()`:
  - `stopOnSignals()` also stops on the IPC message `'shutdown'` (`SHUTDOWN_MESSAGE`, the PM2 convention) when the process has an IPC channel. On Windows an external SIGTERM kills the process without running any handler, so this is how a process manager or `sv` asks for a drain there (ADR-0015).
  - It resolves with the reason (`'SIGINT' | 'SIGTERM' | 'shutdown-message'`), and `sv start` exits with 143 after a SIGTERM (it used to exit 0, so a process manager could not tell a requested stop from anything else). `exitCodeForStop()` maps the reasons.
  - A failing stop is logged ("Graceful shutdown failed") instead of being swallowed.
- b558616: A `hasMany` include that reaches the per-request cap of 1000 children no longer stops silently: a list response carries `meta.truncated` (the relation names, also in the OpenAPI document) and a single-record response the `Strutvane-Truncated-Includes` header. `MAX_INCLUDED_CHILDREN` is exported.
- 02b9b42: Messages, help text, generated files and TSDoc no longer name pnpm, corepack or the absorbed `@strutvane/core`/`cli`/`contracts`/`devkit` packages: the `make:model` field-syntax help talks about the `.cmd` shims of npm and npx, the generated database seeder says `sv db:seed`, built-in error codes are owned by `@strutvane/framework`, and the "install the project dependencies" hint of `sv dev` uses the project's own package manager (`packageManager` field, then the lockfile, else npm; `detectPackageManager` and `installCommand` in `/core`).
- e8c4659: `serve()`, `startServer()` (`sv start`) and `sv dev` report a port they cannot bind as `ServerListenError` with a stable `code` (`PORT_IN_USE`, `PORT_ACCESS_DENIED`, `ADDRESS_NOT_AVAILABLE`), the `host` and `port`, and how to change them (`APP_PORT` or `--port`), instead of a raw Node error. `sv dev` checks the port (and loads the config) before starting its watched child, which would otherwise wait for file changes instead of exiting.
- 75bcdc6: Startup failures are reported as configuration problems, not as framework bugs:
  - A project file that cannot be loaded (a syntax error, a throw at the top level of `config/*.ts`, a model or a route file) is a `ProjectLoadError` (`code: 'PROJECT_INVALID'`) naming the file. The CLI shows it with a fix hint and exits 3. Before it printed Node's bare message ("Unexpected error: Expression expected … report the bug").
  - A provider that fails to boot (the database is down at startup) is `BOOT_FAILED` in the CLI, naming the provider, with a hint to check the service and its settings; a boot that never finishes is `BOOT_TIMEOUT`. Both exit 1.
- 9fc0403: The core logger no longer crashes the app when the reader of stdout goes away (EPIPE from a closed pipe, a restarted log shipper, `sv start | head`). The asynchronous stream error used to become an uncaught exception; now the records are counted as dropped, one warning goes to stderr, and the app keeps running. A broken stderr is contained the same way.
- dd1857b: Migrations (and `db:seed`) on Postgres run on their own connection settings instead of the API pool's: no statement timeout (the API's 5 s limit, or a role default, used to kill long index builds and table rewrites half way), no client-side query timeout, one connection, and a `lock_timeout` of 10 s so a migration waiting on a lock held by live traffic fails fast and can be retried. Set it with `DB_MIGRATION_LOCK_TIMEOUT` (milliseconds, or `30s`, `2min`; `0` waits forever); a malformed value is reported as an invalid environment. The new `pool.lockTimeoutMs` option sets `lock_timeout` for any Postgres connection.
- fa77131: A rejected multipart upload no longer leaves a 2-second timer running after it. The wait for temp files to close now clears its timer. Before, every failed upload kept one timer alive, which delayed process exit and piled up under a flood of bad uploads.
- 54c7518: Custom routes (`app/http/routes/*.ts`) are documented in `/openapi.json`: path parameters, who may call them (`x-strutvane-permission`, public or signed-in) and the problem responses.
- d024d3c: Postgres pools are bounded on the client side too. `pool.connectionTimeoutMs` (default `DEFAULT_CONNECTION_TIMEOUT_MS`, 5 s) limits the wait for a pooled connection, so an exhausted pool or an unreachable server fails the request instead of queueing it forever. `pool.queryTimeoutMs` (default `statementTimeoutMs` + 2 s, or 30 s when the statement timeout is off; `0` disables it) fails a query whose server stopped answering (frozen, partitioned), where `statement_timeout` cannot fire; the connection is destroyed rather than reused.
- 4466a5b: On PGlite, datetimes in years 0001–0099 read back correctly. PGlite parsed `timestamptz` text with JavaScript's legacy date parser, which turned `0050` into `1950` and `0001` into `2001`; the driver now parses timestamps itself (`parsePgTimestamp`).
- 01be015: Row actions no longer require a record-less `can()` to pass: a conditional rule ("members update their own records", a role map `own: true` grant) could never be satisfied on show, update, delete or restore. The action is allowed when `can()` allows it or the row filter is not FALSE; delete and restore are now also checked against the record itself, so a record-level refusal (`deny('delete', { when: … })`) is enforced.
- 7a9a2b3: Requests are bounded: when the app takes longer than `requestTimeoutMs` (a `createHttpApp` option, default `DEFAULT_REQUEST_TIMEOUT_MS`, 30 s; `0` disables it) to produce a response, the client gets a 503 `SERVICE_UNAVAILABLE` problem. It covers handlers, middleware and `http.onRequest` hooks that never settle, which used to hold the client and its socket forever. A failure of the abandoned work after the answer is contained. Routes can set `timeoutMs`; a route that raises `bodyLimit` (an upload endpoint) defaults to `UPLOAD_REQUEST_TIMEOUT_MS` (130 s), above the multipart parser's own deadlines. A streamed response body is not cut once it has started.
- 725f202: `http.onResponse` payloads carry `route`, the matched route template (undefined for unmatched requests). Multipart parsing never writes to a temp file after the upload has been rejected.
- 3d0a1ae: Per-route `bodyLimit` and `timeoutMs` are matched on the path the router serves (percent-decoded), so `/api/v1/upl%6Fads` gets the `/uploads` route's own limit and timeout instead of the app-wide ones. A lowered limit can no longer be dodged by encoding a letter of the path.
- bb30f6a: When a provider fails to boot (`sv dev`, `sv start`), the providers that had already booted are shut down again in reverse order. Before, their connections stayed open and could keep the process running after the error was reported.
- 5080aac: The runtime now loads a `.env` file saved with a UTF-8 byte-order mark correctly. Node's `.env` parser kept the mark as part of the first key, so that variable was silently missing at runtime while `sv env:check` reported it as set.
- 45f4405: `serve()` keeps an `error` listener on the Node server for its whole life. An error the listening server emits (an accept failure such as `EMFILE` when the process runs out of file descriptors) is reported through `onError` instead of crashing the process; the server keeps serving.
- 0bb1421: `RunningServer.close()` (and so `sv start`'s shutdown) drains instead of resetting: it stops accepting connections, closes idle keep-alive connections, lets requests already in flight finish (their responses carry `Connection: close`), and only after a grace period (`close({ graceMs })`, default `DEFAULT_CLOSE_GRACE_MS`, 8 s) cuts what is left, aborting those requests' signals. Before, every in-flight request lost its connection the moment shutdown began. `close()` is also idempotent now; a second call used to reject with "Server is not running".
- 645f1a9: On Windows, the built-UI static file server refuses 8.3 short names (`/ENV~1` would open `.env`) and path segments ending in a dot or a space (`/secret.` opens `secret`), which got past the dot-file check.
- 0545054: `@strutvane/framework/testing` exports the `FactoryAttributes` and `RelatedOptions` types.
- 4d8ebe8: Text fields refuse NUL characters (`invalid_format`) instead of failing inside PostgreSQL with a 500, and required string/text fields refuse empty or whitespace-only values (`required`). Manifest capabilities for row actions follow the same rule as the API: allowed when the row filter is not FALSE, so a member who may edit only their own records still sees Edit and Delete.
